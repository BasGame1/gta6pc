Title: runtime/shims: fill zero DXBC checksums before forwarding root-signature blobs to the host

Body: Under Wine, D3D12SerializeRootSignature and D3D12SerializeVersionedRootSignature return blobs whose 16-byte DXBC MD5 checksum is all zero, confirmed on Wine 9.0 and 11.0 with both the legacy and versioned serialize calls. When the runtime forwards such a blob to the host D3D12XboxSerializeRootSignature or D3D12XboxSerializeVersionedRootSignature the host rejects it with E_INVALIDARG because it verifies the checksum before deserializing. The fix adds copy_dxbc_blob_fill_zero_checksum in d3d12_xs_rootsig.cpp which detects the zero-hash pattern by checking the DXBC magic, the 16-byte hash field being all zero and the total_size field matching the buffer length, then recomputes the checksum with the existing dxbc_checksum helper and writes it back before the host call. Both the unversioned path in d3d12_xs.cpp and the versioned path in d3d12_xs_rootsig.cpp call it. Blobs with a non-zero checksum pass through unchanged so there is no overhead on Windows where the serializer fills the hash correctly. This commit also carries the MAXIMUM_ALLOWED file_system fix which overlaps with draft PR #977; if that PR lands first the file_system.cpp and file_system.h hunks from this branch should be dropped and only the d3d12_xs rootsig hunks submitted. Tested on Linux with Wine 11.22 and RTX 5060: the Windows cross-build root_sig_test.exe passes 0 failures under Wine including the zero-checksum case that previously returned E_INVALIDARG, ctest passes the root_sig test on Linux, and check_no_game_data.py exits 0.
