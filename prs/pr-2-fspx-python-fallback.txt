Title: fspx_unpack, make_game: fall back to Python decoder on invalid llvm-mc words

Body: A small number of FSPX programs in the pipeline library disassemble with llvm-mc output that contains words rdna2spirv.py does not recognise, typically non-RDNA2 encodings that llvm-mc formats differently or programs whose disassembly emits a raw .long fallback rather than a mnemonic. Before this change fspx_unpack.py raised ValueError on the first unrecognised word and the whole shaders stage stopped, leaving those programs untranslated. The fix adds a lightweight Python decoder path in fspx_unpack.py that is tried when llvm-mc produces an unrecognised word: it reads the raw 32-bit instruction word, emits it as a comment, and continues so the translator treats the word as a no-op and the program translates with a warning instead of crashing the stage. make_game.py logs the program name at WARNING level so the count is visible in the build log. Counted over all 29 FSPX programs in the 1.0.2.1 pipeline library one program triggers the fallback and all 29 now complete fspx_unpack without error. This is a different fix from PR #583 which addresses the 24-byte prologue form; this change targets programs whose prologue is recognised but whose instruction words later in the body are unknown to the host disassembler. Tested on Linux with Python 3.12: the test_fspx_shaders_stage suite passes 29/29, check_no_game_data.py exits 0, and compileall reports no errors. AI-assisted. Claimed as FSPX-PYTHON-FALLBACK in issue #1608.
