Title: runtime/shims: map Wine STATUS_NOT_IMPLEMENTED to STATUS_NOT_FOUND in bcrypt_rng

Branch: BasGame1:wine-bcrypt-rng
Target: ubiquitarianism/leonida:main

Claim coordination issue #1608 as: RT-BCRYPT-RNG-STATUS-WINE (new item; no open PR covers
this specific bcrypt_rng Wine STATUS_NOT_IMPLEMENTED → STATUS_NOT_FOUND mapping)

---

### What and why

Windows' `BCryptOpenAlgorithmProvider` returns `STATUS_NOT_FOUND` (0xC0000225) when asked
for an algorithm name it does not recognise. Wine's `bcrypt.dll` returns
`STATUS_NOT_IMPLEMENTED` (0xC0000002) for the same case.

The game's crypto-initialization code checks the return value against `STATUS_NOT_FOUND`
to decide whether to skip an optional algorithm. Under Wine the call returns
`STATUS_NOT_IMPLEMENTED` instead, the check fails, and the game tries to use the NULL
handle — crashing shortly after.

The fix adds a one-liner in the shim's `open_algorithm_provider`: when the host call
returns `STATUS_NOT_IMPLEMENTED` the shim returns `STATUS_NOT_FOUND` to the caller,
matching the Windows answer on both hosts.
