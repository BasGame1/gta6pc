Title: runtime/shims: map Wine STATUS_NOT_IMPLEMENTED to STATUS_NOT_FOUND in bcrypt_rng

Body: Windows BCryptOpenAlgorithmProvider returns STATUS_NOT_FOUND when asked for an algorithm name it does not recognise. Wine bcrypt.dll returns STATUS_NOT_IMPLEMENTED for the same call. The game's crypto-initialisation code checks the return value against STATUS_NOT_FOUND to decide whether to skip an optional algorithm; under Wine the call returns STATUS_NOT_IMPLEMENTED instead, the check fails, and the game tries to use the resulting NULL handle and crashes shortly after. The fix adds a one-liner in the shim's open_algorithm_provider: when the host call returns STATUS_NOT_IMPLEMENTED the shim returns STATUS_NOT_FOUND to the caller, matching the Windows answer on both hosts. Tested on Linux with Wine 11.22: the Windows cross-build bcrypt_rng_test.exe passes 21 of 21 checks under Wine including the previously-failing unknown-algorithm case that now returns STATUS_NOT_FOUND as expected, and check_no_game_data.py exits 0.
